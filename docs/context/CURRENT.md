# class-mid 当前状态

更新时间：2026-09-14

## 当前实现

- 后端入口只有 `server/cmd/game`，默认监听 `127.0.0.1:8080`。
- 注册登录与好友使用 HTTP JSON；农场操作和邮箱使用 WebSocket JSON。
- MySQL 有账号、玩家、作物、仓库、农田、任务定义、玩家任务、邮件、好友 9 张表。
- 新玩家有 50 金币、2 个肥料、16 块空地、6 条仓库记录和一封欢迎邮件。
- 商店有 6 种作物，成熟时间为 30–60 秒。
- 好友关系双向保存。好友可查看农田、偷取成熟作物和投递邮件。
- 偷菜后偷取者获得完整产量和 1 金币，对方地块变为 `NEED_CLEANUP`。
- Qt 已补齐六种作物的选择、商店、仓库和操作请求。好友列表、农场、偷菜和发邮件放在同一个基础弹窗里；邮箱显示系统或玩家用户名。
- Qt 继续使用默认控件和文字，刷新保留当前作物及地块选择，不自动重发写操作。

## 已验证

- `go test ./... -count=1` 和 `go vet ./...` 通过。

- Qt 6.11.2 / MinGW 构建成功。代码简化前最后一次完整冒烟覆盖六种作物、好友、偷菜、中文邮件、倒计时、已读和注销重登并通过，随后按要求删除了 Qt 测试源码和测试目标。Windows 默认控件截图已检查，详见 [Qt 验证记录](../evidence/2026-09-14-qt-features.md)。

## 限制

- Session 只存在进程内，服务重启后需重新登录。
- 凯撒密码只适合课程演示。
- 为保持代码短小，没有请求去重、好友申请确认、偷菜次数限制、分页和成熟推送。
- Qt 自己和好友的生长中地块显示剩余秒数，每秒更新文字；服务器仍负责最终判断是否成熟。
- 本轮 Qt 联调用的是 3307 端口的独立临时 MySQL 实例；未修改原 MySQL 账号、数据或 `.env`。该实例不是 Windows 常驻服务，重启电脑后需要重新启动或配置正式本地数据库。
- 当前仓库不再包含 Qt 自动测试，后续修改主要依靠构建和手动操作检查。
- 修改尚未提交或推送。
