# class-mid 当前代码 Review

审查日期：2026-09-14。范围是单 Go 服务、关系型 MySQL 代码、启动脚本和接口文档。

## 已完成的精简

- 删除 Login、Gate、Coordinator、Shard、Actor 和 Protobuf 运行代码。
- 删除 MemoryStore、整体 `state_json`、旧规则引擎、请求回执和 sqlmock 测试。
- 注册登录与好友使用 HTTP JSON；连续农场操作使用 WebSocket JSON。
- 密码逻辑收敛成一个可讲解的凯撒移位函数。
- 农场业务直接写成事务函数，关键地块使用 `SELECT ... FOR UPDATE`。
- 数据拆为 9 张关系表，可表达 1:1、1:N 和 N:M。

## 当前保留的必要结构

- `model.go` 集中定义 JSON 数据，Go 和 Qt 字段容易对照。
- `http.go` 处理短请求和 Session，`websocket.go` 处理长连接消息循环。
- `game.go` 与 `friend.go` 分开，避免单文件同时包含所有农场和社交操作。
- `mysql.go` 负责建表、注册初始化和组合查询，SQL 仍然直接可见。
- `mails`、`friends`、`plots` 等数据独立成表，避免一次操作重写整个玩家 JSON。

## 已知简化与影响

- Session 只在服务器内存中，重启后重新登录。
- 写请求没有 request_id 去重。网络中断后客户端先读取快照，不自动重发未知结果。
- 好友添加后立即成为双向好友，没有申请和同意过程。
- 偷菜没有每日次数和防重复记录，地块成熟后最先成功的请求取得全部产量。
- HTTP 好友发信接口在插入后按新邮件 ID 与 B 的 ID 读回这一封，用于演示且不会暴露 B 的其他邮件。
- 空切片使用 `omitempty` 时字段可能省略，Qt 解析时将缺失字段视为空数组。
- 登录查询发生数据库错误时目前会统一显示账号或密码错误；如果最终版需要运维诊断，可再区分数据库故障。
