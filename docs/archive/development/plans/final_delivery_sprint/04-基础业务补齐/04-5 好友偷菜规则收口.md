# 04-5 好友偷菜规则收口

> **Agent 执行要求：** 按任务顺序实施；先写测试，再修改实现。开始前检查其他任务是否正在修改 FriendInteraction Saga，禁止覆盖并行改动。

## 1. 目标

支持全部 11 种作物偷菜，并保持：

- 访客 Zone 先预留仓库容量；
- 农场主 Zone 只进行一次权威校验和扣减；
- 不增加额外的农场主查询；
- 复用现有 FriendInteraction Saga；
- 宠物护主结果在 Saga 中冻结；
- 偷菜成功后通过已完成的广播链路推送地块变化。

## 2. 固定业务规则

每次成功偷取数量固定为 `1`。

同一访客在同一地块的同一轮作物中最多偷取一次。

```text
protected_owner_yield = ceil(base_yield / 2)
max_steal_times = base_yield - protected_owner_yield
```

| 基础产量 | 农场主保底 | 最大被偷次数 |
|---:|---:|---:|
| 3 | 2 | 1 |
| 4 | 2 | 2 |
| 5 | 3 | 2 |
| 6 | 3 | 3 |

种植时继续把以下数值冻结到地块：

- `base_yield`
- `steal_quantity`
- `protected_owner_yield`
- `max_steal_times`

历史已经种植的地块使用其原有冻结值，不重新计算。

## 3. 最终链路

```text
Client
  -> Gate
  -> 访客 Zone：创建或恢复 FriendInteraction
  -> 访客 Actor：ReserveSteal
  -> 农场主 Zone：ApplyStealOnOwner
  -> 访客 Actor：CommitSteal
  -> Dispatcher：广播农场主地块 Patch
  -> Gate
  -> 在线农场主和访客 Client
```

### 请求携带

偷菜请求至少携带：

- `owner_player_id`
- `visit_id`
- `plot_id`
- `expected_crop_item_id`
- `farm_view_epoch`
- `farm_view_seq`

`expected_crop_item_id` 来自访客已经获得的公开农场视图，只用于预留仓库和提前拒绝明显过期的请求，不能代替农场主 Actor 的权威校验。

## 4. Saga 状态机

保持现有状态：

```text
INIT
  -> VISITOR_RESERVED
  -> OWNER_APPLIED
  -> VISITOR_COMMITTED
  -> COMPLETED
```

失败补偿：

```text
INIT / VISITOR_RESERVED
  -> RELEASING
  -> ABORTED
```

约束：

- `OWNER_APPLIED` 之后不能释放仓库预留；
- `OWNER_APPLIED` 之后必须持续重试 `CommitSteal`；
- 每一步使用 `interaction_id` 和 Actor receipt 去重；
- Saga 恢复所需的作物 ID、数量和版本信息必须持久化，不能重新调用 `SoleStealableCrop()` 推导。
