# 宠物最小闭环 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` or `superpowers:executing-plans`.
> 先检查另一个任务是否正在修改 FriendInteraction Saga；禁止覆盖并行修改。

**Goal:** 实现宠物购买、出战、狗粮续时和偷菜护主惩罚，并提供文字型 H5 宠物窗口。

**Architecture:** 宠物所有权、当前出战宠物和狗粮有效期属于 Player Actor，并随 Checkpoint 持久化。偷菜时由 owner Actor 根据出战宠物和狗粮有效期进行一次护主判定，将结果冻结到 FriendInteraction Saga；访客 Actor 在获得作物时原子扣除罚款金币。广播仍只同步公开地块变化，宠物私有状态通过命令响应或 Player Patch 返回。

**Tech Stack:** Go、Vue 3、Protobuf、Player Actor、ConfigSnapshot、FriendInteraction Saga、Tcaplus Checkpoint。

## Global Constraints

- 玩家初始没有宠物。
- 玩家可以永久拥有多只宠物，但一次只能派出一只。
- 已购买宠物之间免费切换。
- 狗粮属于仓库物品。
- 使用一份狗粮，在现有有效期基础上增加 24 小时。
- 存在未过期狗粮且已派出宠物时，护主 Buff 才生效。
- 偷菜护主触发后，偷菜仍然成功。
- 访客罚款为 `min(当前金币, 配置罚款)`，最低扣到 0。
- 罚款金币直接销毁，不转移给主人。
- 同一个 Interaction 只抽取一次，重试不得重新判定或重复扣款。
- 所有价格、有效时间、概率和罚款值来自服务端配置。
- 前端不执行概率判定和金币计算。

## 1. 已确认业务规则

### 宠物配置

| 宠物 | 价格 | 护主概率 | 访客罚款 |
|---|---:|---:|---:|
| 田园犬 | 5 金币 | 10% | 2 金币 |
| 牧羊犬 | 10 金币 | 10% | 4 金币 |

### 狗粮配置

| 配置 | 数值 |
|---|---:|
| 狗粮价格 | 5 金币 |
| 每份有效时间 | 24 小时 |
| 仓库消耗 | 每次喂食消耗 1 份 |

### 出战规则

```text
未购买宠物
-> 不能派出

已购买宠物
-> 可以免费派出或切换

一次只能派出一个宠物
```

狗粮有效期属于玩家宠物系统，不属于某一只宠物。

切换出战宠物不会清除剩余狗粮时间。

### 狗粮续时

```text
如果当前未生效：
    active_until = now + 24h

如果当前仍生效：
    active_until = active_until + 24h
```

### 护主条件

只有同时满足以下条件才参与概率判定：

```text
active_pet_id != 0
AND now < food_active_until_ms
AND 当前操作是合法偷菜
```

### 护主结果

```text
偷菜仍然成功
访客照常获得作物
访客额外扣除金币
主人金币不变
```

## 2. 配置模型

在现有服务端 ConfigSnapshot 中增加宠物配置，不另建 ConfigSvr。

建议逻辑结构：

```go
type PetConfig struct {
    PetID                  uint32
    Name                   string
    PriceCoins             int64
    GuardProbabilityBPS    uint32
    GuardPenaltyCoins      int64
    ConfigVersion          uint64
    Enabled                bool
}

type PetFoodConfig struct {
    ItemID                 uint32
    PriceCoins             int64
    DurationSeconds        uint64
    PriceVersion           uint64
    ConfigVersion          uint64
    Enabled                bool
}
```

概率使用万分比整数：

```text
10% = 1000 BPS
100% = 10000 BPS
```

禁止在权威判定中使用浮点数。

开发配置：

```text
田园犬：
pet_id = 1
price_coins = 5
guard_probability_bps = 1000
guard_penalty_coins = 2

牧羊犬：
pet_id = 2
price_coins = 10
guard_probability_bps = 1000
guard_penalty_coins = 4

狗粮：
item_id = 新的稳定Item ID
price_coins = 5
duration_seconds = 86400
```

具体 Item ID 必须检查现有配置后选择未占用值。

## 3. Player Checkpoint

建议在 `PlayerCheckpointV1` 末尾追加字段，不复用旧字段号：

```proto
message PetStateRecord {
  repeated uint32 owned_pet_ids = 1;
  uint32 active_pet_id = 2;
  int64 food_active_until_ms = 3;
}

message PlayerCheckpointV1 {
  // existing fields...
  PetStateRecord pet_state = <new_field_number>;
}
```

规则：

- `owned_pet_ids` 唯一并升序；
- `active_pet_id == 0` 表示未派出宠物；
- 非零 `active_pet_id` 必须存在于 `owned_pet_ids`；
- `food_active_until_ms == 0` 表示从未喂食；
- 狗粮是否有效由服务器当前时间与 `food_active_until_ms` 比较；
- 不持久化需要 Tick 的饱食百分比。

客户端显示：

```text
now < food_active_until_ms：
饱食状态：充足
剩余时间：...

now >= food_active_until_ms：
饱食状态：饥饿
护主状态：未生效
```

## 4. 协议范围

建议增加最小命令：

```text
GET_PET_PANEL
BUY_PET
DEPLOY_PET
BUY_PET_FOOD
FEED_PET
```

其中：

### GET_PET_PANEL

返回：

- 当前宠物商店配置；
- 已拥有宠物；
- 当前出战宠物；
- 狗粮库存；
- 狗粮有效截止时间；
- 护主 Buff 是否生效。

### BUY_PET

输入：

```text
pet_id
price_version/config_version
request_id
```

结果：

```text
扣除金币
-> 永久加入 owned_pet_ids
```

重复购买已拥有宠物返回确定错误，不重复扣金币。

### DEPLOY_PET

输入：

```text
pet_id
request_id
```

结果：

```text
active_pet_id = pet_id
```

只能派出已购买宠物。

### BUY_PET_FOOD

输入：

```text
quantity
price_version
request_id
```

结果：

```text
扣除金币
-> 狗粮加入仓库
```

数量限制复用当前商店购买边界。

### FEED_PET

输入：

```text
request_id
```

结果：

```text
消耗1份狗粮
-> food_active_until_ms增加24小时
```

没有出战宠物时是否允许提前喂食：本计划允许，狗粮时间仍会立即开始计算。

## 8. 停止条件

- 护主随机结果无法持久化到 Saga 或 owner receipt；
- Saga 重试会重新抽取；
- 访客金币扣除发生在 Actor mailbox 外；
- 为实现宠物需要创建第二套跨 Actor 事务；
- 前端成为概率或价格权威；
- 狗粮需要 Runtime 高频 Tick；
- 与正在进行的好友任务发生不可安全合并的冲突。
