# HARVEST command evidence

## Claim boundary

Automated tests prove that `HARVEST`:

1. requires a known `MATURE` plot;
2. computes `base_yield - stolen_quantity` from frozen Actor state;
3. rejects a new item type above 100 types without changing inventory, plot,
   task progress or `player_seq`;
4. rejects a resulting stack above 300 with the same all-or-nothing behavior;
5. adds the full yield, changes the plot to `NEED_CLEANUP` and advances the
   harvest task on success;
6. increments `player_seq` once, marks Dirty and serializes a valid checkpoint;
7. returns a stored same-ID replay without harvesting twice.

A live in-memory four-process run also proves that the protocol path can receive
natural maturity at `player_seq=4`, issue `HARVEST`, and receive the correlated
`player_seq=5` response with three crop items and a `NEED_CLEANUP` plot.

An owner-run MySQL 8.4.11 extension proves that the same flow was flushed under
the local Fence and checkpoint CAS, all four services stopped, and a fresh
stack recovered the harvested checkpoint.

## Observed result

```text

HARVEST player_seq=5 crop_item_1002=3
  plot_state=NEED_CLEANUP replayed=true
PASS TestAuthenticatedSnapshot (72.02s)
RESULT maturity_push_e2e=PASS
```

The focused checkpoint test wrote `player_seq=5`,
`checkpoint_revision=6`, crop item `1002` quantity `3`, harvest task progress
`1/1`, and a `NEED_CLEANUP` plot under expected persisted revision 5.

## Live MySQL restart result

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File .\tests\e2e\run-mysql-restart-recovery.ps1 `
  -HostName 127.0.0.1 -Port 3306 -User classicfarm
```

Observed first stack:

```text
PLAYER_STATE_CHANGED reason=MATURED player_seq=4
HARVEST player_seq=5 crop_item_1002=3
  plot_state=NEED_CLEANUP replayed=true
RESULT authenticated_snapshot_e2e=PASS adapter=mysql-restart-register
```

After all four services restarted:

```text
HTTP_AUTH mode=login player_id=7
SNAPSHOT ... player_seq=5 coins=4 seed_quantity=2
  plot_state=NEED_CLEANUP
RESULT authenticated_snapshot_e2e=PASS adapter=mysql-restart-login
RESULT mysql_restart_recovery_e2e=PASS
```

The snapshot assertion also checked crop item `1002` quantity 3. This proves
recovery after the maturity and harvest had already completed; it does not
prove restarting while a fertilizer interval or maturity deadline is still in
flight.
