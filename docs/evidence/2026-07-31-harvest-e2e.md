# HARVEST command evidence

## Claim boundary

Automated tests prove that `HARVEST`:

1. requires a known `MATURE` plot;
2. computes `base_yield - stolen_quantity` from frozen Actor state;
3. rejects a new item type above 100 types without changing inventory, plot,
   task progress or `player_seq`;
4. rejects a resulting stack above 300 with the same all-or-nothing behavior;
5. adds the full yield, changes the plot to `NEED_CLEANUP` and advances the
   harvest task on success;
6. increments `player_seq` once, marks Dirty and serializes a valid checkpoint;
7. returns a stored same-ID replay without harvesting twice.

A live in-memory four-process run also proves that the protocol path can receive
natural maturity at `player_seq=4`, issue `HARVEST`, and receive the correlated
`player_seq=5` response with three crop items and a `NEED_CLEANUP` plot.

It does not yet prove MySQL restart recovery of the harvested checkpoint. The
password-prompted restart wrapper has been extended to perform and recover this
flow, but has not been owner-run after this change.
