## 1. 交付目标

在 2026-08-16 前完成：

- 题目要求的基础业务；
- 手机 HTTPS 可体验版本；
- 最小弱网和更新可靠性；
- 写路径、广播、Dirty 和资源压测；
- 3000 万 DAU 容量设计；
- 完整 E2E 和演示候选版本。

在 2026-08-18 前冻结材料，2026-08-19—20 只排练和修复演示阻断问题。

## 2. 全局约束

- 继续使用 Stateful Player Actor Zone V3、4096 Shard、Coordinator、Lease 和 Fence。
- 账号认证属于 LoginSvr；农田、仓库、任务、宠物和图鉴属于 Player Actor。
- LoginSvr 注册成功只代表账号创建成功，不要求农田已经初始化。
- 新玩家农田由 Owner Zone 在 Actor 第一次激活时创建。
- 客户端负责使用同一 `request_id` 重发；权威去重不能只放 Gate 内存。
- FriendInteraction Saga 的 reservation、receipt 和补偿不能被普通幂等框架替代。
- 3000 万 DAU 是容量设计目标，不得表述为本地实测能力。
- 每个完成项必须有测试或 `docs/evidence/` 证据。
- 8 月 16 日后禁止新增功能、数据库或架构机制。

## 4. 阶段计划

### 01：Actor 先创建后 Load

**目标：**

```text
首个请求
-> 注册唯一 Loading Actor/mailbox
-> Load 作为 mailbox 第一项任务
-> 并发请求进入同一 mailbox
-> 初始化完成后依次执行
```

**完成标准：**

- 100 个并发首请求只创建一个 Actor；
- `Store.Load` 只执行一次；
- 初始化失败可重试且不遗留僵尸 Actor；
- Loading Actor 正确参与 Drain 和 Runtime Close；
- race、双 Zone、迁移和好友互动回归通过。

**计划：**

```text
01-Actor先创建后Load.md
```

### 02：新玩家农田延迟初始化

**目标：**

分离账号数据和游戏业务数据：

```text
LoginSvr 注册
-> 只创建账号、PlayerID、Session

首次游戏请求
-> Gate 路由到 Owner Zone
-> Zone 创建 Loading Actor
-> Store.Load 返回 NotFound
-> Actor mailbox 创建初始农田状态
-> 持久化初始 checkpoint
-> Actor Ready
-> 执行首个命令
```

**完成标准：**

- LoginSvr 不再构造 Player checkpoint 或默认农田；
- 注册成功不依赖 Zone 或农田 Store；
- Store 的 `NotFound` 与临时错误严格区分；
- 只有当前 Owner Zone 可以初始化农田；
- 并发首请求只初始化一次；
- 初始 checkpoint 使用创建/CAS 语义，不能覆盖已有数据；
- 初始化失败后账号仍可登录，后续游戏请求可以重试；
- 初始化配置和默认状态有确定版本；
- 注册、首次进入、并发初始化和重启恢复 E2E 通过。

**计划：**

```text
02-新玩家农田延迟初始化.md
```

### 03：广播与业务解耦（已完成 2026-08-10）

**目标：**

```text
业务命令
-> 产生领域变化
-> Actor 提交阶段生成公开视图事件
-> 独立 Dispatcher 查询接收者并投递 Gate
```

**完成标准：**

- 业务 handler 不查询访客、不选择 Gate、不直接 Push；
- Runtime 不再按 Action switch 猜测公开地块变化；
- Patch 和 sequence 在 owner Actor mailbox 内生成；
- 广播失败不回滚业务；
- FriendInteraction 只在权威持久化完成后广播；
- 客户端 gap/dup/epoch 恢复语义有单元测试（三客户端 live E2E 可选未重跑）。

**计划 / 证据：**

```text
03-广播与业务解耦.md
../../evidence/2026-08-10-farm-broadcast-separation.md
```

+ 重启恢复

**完成标准：**

- 未登录用户点击分享链接后，登录完成继续自动加好友；
- 偷菜满足保护量、次数、并发和 Saga 恢复规则。

### 06：弱网与传输可靠性

**目标：**

- 客户端自动重连；
- 重新获取 Ticket 和 AUTH；
- 未决命令使用原 `request_id` 重发；
- 普通 Player 命令使用统一权威去重；
- Gate Push 使用有界队列；
- sequence gap 拉完整快照。

**完成标准：**

验证断网发生在以下三个时点：

1. 请求发送前；
2. 服务端执行后、响应返回前；
3. 客户端收到响应后。

最终业务只生效一次，客户端恢复到权威状态。

**计划：**

```text
06-弱网与传输可靠性.md
```

### 07：路由、调度、日志与平滑更新

**目标：**

- Coordinator 主动发布版本化路由变化；
- 周期快照和 `NOT_OWNER` 刷新作为兜底；
- Actor 按最近业务到期时间注册唤醒；
- Kubernetes 日志支持 Debug 过滤和 request ID 查询；
- Gate/Zone 支持 readiness、Drain 和 preStop。

**完成标准：**

- 路由迁移后 Gate 在下一请求前更新；
- Kubernetes 只负责发现 Zone，不直接授予 Shard ownership；
- Runtime 不再每秒同步遍历全部 Actor；
- 跨服务请求可通过 `request_id` 追踪；
- Zone 正常退出前排空 mailbox 并 flush Dirty；
- 滚动更新和强制超时边界有测试或证据。

**计划：**

## 6. 止损规则

### 08-11 架构任务未完成

- 停止扩大重构；
- 不提前迁移全部幂等逻辑；
- 保留已通过测试的最小改动；
- 优先补齐产品基础要求。

### 08-13 可靠性未完成

优先保留：

1. 自动重连；
2. 相同 `request_id` 重发；
3. 权威去重；
4. sequence gap 拉快照；
5. 有界 Push 队列；
6. readiness 和 Dirty flush。

主动路由通知、Actor 调度和日志平台可降为最小 POC 加准确设计。

### 08-15 压测时间不足

按以下顺序保留：

1. Actor 写路径；
2. Dirty/Tcaplus；
3. CPU、内存和 GC；
4. Push/广播。

不得只使用旧快照读 QPS 宣称完成性能验证。

### 08-16 后

禁止新增：

- 数据库；
- 共识算法；
- 自动故障转移；
- 复杂宠物玩法；
- 运营后台；
- 非必要 UI 重写。

只修：

- 演示阻断；
- 数据错误；
- 安全问题；
- 测试证据错误；
- 答辩材料不准确。
