# Recoverable Normal Migration Worker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:executing-plans` and `superpowers:test-driven-development`.
> Execute after Phase 05. This phase handles planned REBALANCE/DRAIN only;
> abrupt DEAD failover belongs to Phase 07.

**Goal:** Consume persistent MigrationTasks and move one Shard through
Source Drain, durable Fence and TargetReady to durable ACTIVE Current with
restart recovery at every boundary.

**Architecture:** Replace the monolithic synchronous migration handler with a
queue/worker/state-machine package while reusing Zone lifecycle RPCs,
`MigrationProgress`, RouteStore and Fence CAS. The worker persists each step
before the next side effect and publishes only durable ACTIVE snapshots.

## Global Constraints

- State path:
  `PLANNED -> SOURCE_DRAINING -> SOURCE_FLUSHED -> ROUTE_PREPARING ->
  FENCE_ADVANCED -> TARGET_LOADING -> TARGET_READY -> ROUTE_ACTIVE -> COMPLETED`.
- Before Fence, Source may be restored; after Fence, never return to old epoch.
- Active ShardRoute must commit before in-memory Current and Publisher.
- No Actor prewarming; TargetReady validates ownership/fence only.
- Initial limits: global 8, per Source 2, per Target 2.
- Requests during migration return retryable `ZONE_MIGRATING`.
- Keep the existing admin `move` endpoint, but make it return
  `202 Accepted + task_id` after creating a DRAIN task; it must not run a
  second synchronous migration path.
- Reuse existing `MigrationTask`, `MigrationProgress`, `ShardFence` and
  `ShardRoute` tables. Phase 06 adds no Tcaplus table or protobuf field.
- Keep the worker disabled by default until the final live gate.

**Interface additions:**

```go
Claim(context.Context, uint32, []byte) (Task, error)
Retry(context.Context, uint32, []byte, uint32, int64, string) error
Complete(context.Context, uint32, []byte) error
```

- `Claim` changes the exact PLANNED task to RUNNING with record-version CAS.
- Exact RUNNING replay returns the same task so Coordinator restart can resume.
- `Retry` returns RUNNING to PLANNED, persists attempt/retry/error and requires
  the exact immutable task ID.
- `Complete` changes the exact RUNNING task to COMPLETED; terminal replay is
  idempotent only for the same task ID.
- All methods use the existing bounded CAS retry loop.

## Task 3: Implement one-Shard normal state machine

**Files:**
- Create: `server/internal/coordinator/migration/executor.go`
- Create: `server/internal/coordinator/migration/executor_test.go`

**Execution rules:**

1. Reload the exact RUNNING Task and Current; complete if Current already
   equals Target, otherwise reject any frozen Source mismatch.
2. Persist `SOURCE_DRAINING` Progress before Source Drain.
3. Source Drain is idempotent by transition ID, blocks activation/requests,
   drains mailbox, flushes Dirty and
   returns manifest.
4. Persist `SOURCE_FLUSHED` with manifest.
5. Persist the frozen prepared Route, call RouteStore.CommitPreparing, persist
   `ROUTE_PREPARING`, then replace the in-memory map and immediately
   publish PREPARING so every SDK pauses that Shard as `ZONE_MIGRATING`.
6. Advance Fence and persist `FENCE_ADVANCED`.
7. Persist `TARGET_LOADING`; Target Prepare verifies manifest/Fence without
   loading every Actor; persist `TARGET_READY`.
8. RouteStore.CommitActive and persist `ROUTE_ACTIVE`.
9. Replace in-memory Current and immediately PublishRoutes.
10. Best-effort Target refresh; complete Progress, then complete Task.

- [x] Assert Fence/ACTIVE failure never publishes Target ACTIVE.
- [x] Assert failure before Fence can Restore Source; after Fence only continue.
