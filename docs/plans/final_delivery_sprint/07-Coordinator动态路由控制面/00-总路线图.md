# Coordinator Dynamic Routing Control Plane Implementation Roadmap

> **For agentic workers:** Do not execute this roadmap as one task. Execute one
> phase document at a time. Each phase must preserve the static dual-Zone
> regression until its replacement path is verified.

**Goal:** Evolve the current static, single-process Coordinator into the
ADR-0012 control plane without rewriting the working Shard, Fence, Drain or
Gate-cache foundations.

**Architecture:** Keep Player→4096-Shard hashing and existing Zone ownership
validation. Add a durable Current Route before adding push delivery; then add
SDK Watch, Kubernetes membership, Current/Desired planning, queued migration,
failover, Leader Election and cold-load protection in dependency order.

**Tech Stack:** Go 1.26, Protobuf/gRPC, Tcaplus, Kubernetes EndpointSlice/Pod
Watch, Kubernetes Lease, kind.

## Global Constraints

- ADR-0012 is authoritative for this roadmap.
- Do not change `ShardCount=4096`, `StableHash64` or `ShardForPlayer`.
- Ordinary player commands must not synchronously query Coordinator.
- Never publish a new Active owner before Fence and Active ShardRoute succeed.
- Kubernetes discovery never grants ownership.
- Preserve `NOT_OWNER` and HTTP snapshot lookup as fallback paths.
- Do not add Actor prewarming in this roadmap.
- Configuration defaults are assumptions until load-test evidence exists.
- Every phase updates `docs/context/CURRENT.md` only after verification.
- Measurements belong in `docs/evidence/` and must be labelled measured,
  derived or assumed.

## Cross-Phase Data Flow

```text
EndpointSlice/Pod
  -> Membership(HEALTHY/SUSPECT/DEAD)
  -> PlacementPlanner computes Desired
  -> Current/Desired diff creates MigrationTask
  -> MigrationWorker drains or fails over one Shard
  -> Fence CAS
  -> Target ShardReady
  -> Active ShardRoute CAS
  -> in-memory Current
  -> Publisher RouteBatch
  -> embedded SDK cache in Gate/Info/Zone
```

## Phase Gates

### Gate after Phase 1

- Coordinator restart restores the same Current owner/epoch/version.
- Active ShardRoute failure cannot change the published/in-memory owner.
- Existing static migration still passes.

### Gate after Phase 2

- Gate/Info/Zone apply committed changes without waiting for a business
  `NOT_OWNER` response.
- Duplicate/gap/slow subscriber tests recover by snapshot resync.
- Ordinary cache hits perform zero Coordinator lookups.

### Gate after Phase 4

- Eight stable Zone IDs produce deterministic Desired placement.
- Adding a ninth Zone creates tasks only for changed Desired owners.
- No Planner function mutates Current Route.

### Gate after Phase 6

- Transient connection failure enters SUSPECT and can recover without epoch
  change.
- Confirmed DEAD performs failover without Source Drain.
- Storage failure never becomes Zone death.

### Gate after Phase 7

- Only the Lease holder mutates control state.
- A stale Leader's CAS cannot overwrite newer Current/Fence/Progress.
- A new Leader resumes open migrations from Tcaplus.

### Final gate

- Expansion, graceful drain, abrupt death and blue-green flows have reproducible
  evidence.
- Cold-load tests report Tcaplus QPS/latency/queue/error behavior.
- No result claims production 30-million-DAU capability.

## Rollback Rule

Every phase keeps a configuration switch for the last verified path until the
new path passes its phase gate. Rollback may select the previous path; it must
not delete or rewrite newer Fence/Route epochs. Never use a rollback that
recomputes Current from a static Zone list after durable ShardRoute exists.
