# 用户生涯、作物图鉴与多作物配置 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `superpowers:subagent-driven-development` or `superpowers:executing-plans`.
> 本计划复用现有配置驱动的种植链路，禁止为每种作物复制业务函数。

**Goal:** 增加公开用户生涯、农场主私有图鉴和 10 种新作物，并让商店、种植、成熟、收获、出售和 H5 全部按配置支持多作物。

**Architecture:** 生涯统计和私有图鉴属于 Player Actor，并随 Checkpoint 持久化。自己农田成功收获时累计实际入仓数量并点亮图鉴；偷菜 visitor commit 时累计实际获得数量。公开快照只包含生涯，私有 PlayerSnapshot 包含生涯和图鉴。

**Tech Stack:** Go、Vue 3、Protobuf、Player Actor、ConfigSnapshot、Tcaplus Checkpoint、FarmView。

## Global Constraints

- 最终共 11 种作物：保留原作物并新增 10 种。
- 新增作物复用同一套 BUY_SEEDS、PLANT、成长、HARVEST 和 SELL_CROP。
- 禁止新增 `plantCarrot`、`harvestCorn` 等作物专用业务函数。
- 累计收获只计算自己农田实际进入仓库的数量。
- 累计摘取只计算偷菜实际进入访客仓库的数量。
- 偷菜所得不解锁图鉴。
- 邮件、商店或其他来源获得作物不解锁图鉴。
- 图鉴只有农场主自己可见。
- 用户生涯对农场主和访客可见。
- 旧玩家不回填历史数据，从功能上线后开始累计。
- 多作物偷菜适配放在 `04-5-好友偷菜规则收口.md`。

## 1. 业务规则

### 1.1 用户生涯

保存两个累计值：

```text
total_harvested_crop_quantity
total_stolen_crop_quantity
```

含义：

```text
total_harvested_crop_quantity
= 玩家从自己农田成功收获并实际进入仓库的数量

total_stolen_crop_quantity
= 玩家偷取好友作物并实际进入仓库的数量
```

示例：

```text
某块地基础产量6
已被好友偷走2
农场主最终收获4

农场主：
total_harvested_crop_quantity += 4

偷菜玩家：
total_stolen_crop_quantity += 2
```

不计入累计收获：

- 偷菜所得；
- 邮件附件；
- 商店购买；
- 管理命令；
- 失败或重复的收获请求。

### 1.2 私有图鉴

图鉴记录玩家亲自种植并成功收获过的作物：

```text
自己HARVEST成功
-> 点亮crop_id

偷菜获得
-> 不点亮

邮件或其他来源获得
-> 不点亮
```

同一种作物只解锁一次。

图鉴不发放额外奖励，避免扩大范围。

### 1.3 可见性

| 数据 | 自己 | 访客 |
|---|---|---|
| 用户名 | 可见 | 可见 |
| 累计收获数量 | 可见 | 可见 |
| 累计摘取数量 | 可见 | 可见 |
| 图鉴解锁状态 | 可见 | 不可见 |

前端用户名按钮表示当前正在查看的农场主人：

```text
自己的农场
-> 点击自己的用户名
-> 显示“用户生涯”和“我的图鉴”

好友农场
-> 点击好友用户名
-> 只显示“用户生涯”
-> 不返回、不渲染好友私有图鉴
```

## 3. 数据模型

建议追加：

```proto
message PlayerCareerRecord {
  uint64 total_harvested_crop_quantity = 1;
  uint64 total_stolen_crop_quantity = 2;
}

message CropCompendiumRecord {
  repeated uint32 unlocked_crop_ids = 1;
}

message PlayerCheckpointV1 {
  // existing fields...
  PlayerCareerRecord career = <new_field_number>;
  CropCompendiumRecord crop_compendium = <new_field_number>;
}
```

规则：

- 累计数量使用 `uint64`；
- 增加时检查溢出；
- `unlocked_crop_ids` 唯一并按升序保存；
- 旧 Checkpoint 缺少字段时按零值处理；
- 不根据仓库或旧 Interaction Receipt 回填历史；
- 图鉴只保存 `crop_id`，名称和显示来自当前配置。

## 8. 停止条件

- 为每种作物复制种植或收获函数；
- 使用仓库现有数量反推历史生涯；
- 偷菜、邮件或商店获得作物会点亮图鉴；
- 访客响应包含好友私有图鉴；
- 生涯累计发生在 Actor mailbox 外；
- 多作物配置导致当前单作物偷菜逻辑返回错误奖励；
- 为完成本计划必须同时重写完整偷菜 Saga；
- 与其他好友任务发生不可安全合并的冲突。
