# 分享链接自动加好友 Implementation Plan

> **For agentic workers:** 本阶段只完成本地链接和双浏览器 E2E。公网域名、Nginx、HTTPS 和手机外网访问留到第 05 阶段。

**Goal:** 基于现有好友码生成分享链接；用户打开链接并完成登录或注册后自动兑换好友码。只有被邀请人第一次成功添加好友时，双方各获得一封奖励邮件。

**Architecture:** 分享链接只是现有 Friend Code 的 URL 表示，不新建第二套邀请 Token。H5 保存 pending friend code，认证完成后自动调用现有兑换流程。FriendSvr 使用以 invitee ID 为主键的首次好友奖励资格记录保证并发下只奖励一次。

**Tech Stack:** Go、Vue 3、FriendSvr、Friend Link Saga、MailSvr、Tcaplus。

## Global Constraints

- 链接有效期与好友码完全一致。
- 链接可以被多个不同玩家使用。
- 每个玩家兑换同一好友码必须幂等。
- GET 页面本身不能直接修改好友关系。
- 只有认证完成后，由 H5 发送兑换命令。
- 自己不能添加自己。
- 已经是好友时不重复建关系或发奖励。
- 只有被邀请人第一次拥有好友时才产生奖励。
- 双方奖励均为 10 金币和 4 个葡萄种子。
- 奖励通过 MailSvr 邮件手动领取。
- 当前只验证 localhost，不写死未来域名。

## 1. 链接格式

配置：

```text
PUBLIC_WEB_BASE_URL
```

默认：

```text
http://localhost:5173
```

生成链接：

```text
{PUBLIC_WEB_BASE_URL}/invite/friend?code={friend_code}
```

示例：

```text
http://localhost:5173/invite/friend?code=ABC123
```

以后云端只修改：

```text
PUBLIC_WEB_BASE_URL=https://farm.example.com
```

禁止：

- 在 Go 代码中写死 localhost；
- 在 H5 中拼接生产域名；
- 根据客户端提供的 Base URL 生成链接。

## 2. 业务流程

### 已登录用户

```text
打开分享链接
-> H5读取code
-> WebSocket已认证
-> 自动发送REDEEM_FRIEND_CODE
-> FriendSvr建立关系
-> H5显示结果
```

### 未登录用户

```text
打开分享链接
-> H5读取code
-> 保存pending_friend_code
-> 跳转登录/注册
-> 完成Session和WS AUTH
-> 读取pending_friend_code
-> 自动发送REDEEM_FRIEND_CODE
-> 成功或终结失败后清除pending code
```

### 页面 GET 安全边界

```text
浏览器打开URL
-> 只加载H5并保存code
```

不能在 HTTP GET 时直接建立好友关系，避免：

- 链接预览机器人触发业务；
- 浏览器预加载触发业务；
- 未认证请求修改状态；
- GET 请求承担写语义。

## 3. 首次好友奖励

奖励条件：

```text
好友关系本次新建成功
AND invitee此前从未成功添加过好友
```

满足条件时：

```text
邀请人：10金币 + 4个葡萄种子
被邀请人：10金币 + 4个葡萄种子
```

不满足条件时：

```text
好友关系仍可正常建立
但双方都没有邀请奖励
```

以下情况不奖励：

- 被邀请人已经有过好友；
- 双方已经是好友；
- 重复点击链接；
- 重复兑换好友码；
- 自己添加自己；
- 好友码过期；
- 好友列表已满；
- 建立关系失败。

## 4. 首次好友并发控制

禁止：

```text
查询invitee好友数为0
-> 直接发奖励
```

两个并发邀请可能同时看到 0。

建议增加：

```text
FirstFriendReward
```

逻辑记录：

```text
invitee_player_id     // 主键
inviter_player_id
relation_id
friend_code
claimed_at_ms
```

关系建立成功后：

```text
InsertIfAbsent(invitee_player_id)
```

结果：

```text
插入成功：
当前relation获得唯一首次好友奖励资格

记录已存在：
不发送奖励
```

如果两个好友关系并发建立，只有一个 relation 能成功插入。

## 5. 奖励邮件

奖励邮件使用稳定 source event ID：

```text
first-friend:{invitee_player_id}:inviter
first-friend:{invitee_player_id}:invitee
```

邮件内容：

```text
标题：首次好友奖励

邀请人正文：
你邀请了一位新玩家成为好友。

被邀请人正文：
你成功添加了第一位好友。

附件：
coins = 10
items = [
  {
    item_id: grape_seed_item_id,
    quantity: 4
  }
]
```

MailSvr 必须按 source event ID 去重。

即使 FriendSvr 或 MailSvr 重试，也不能创建重复奖励邮件。

### Task 3：首次好友奖励资格

- [ ] 增加 `FirstFriendRewardStore`：

```go
TryClaim(
    inviteePlayerID,
    inviterPlayerID,
    relationID,
    friendCode,
    now,
) (claimed bool, error)
```

- [ ] Tcaplus 使用 invitee player ID 作为唯一主键。
- [ ] 只有关系已经 ACTIVE 后才允许 TryClaim。
- [ ] 插入成功表示当前 relation 获得奖励。
- [ ] 已存在表示不奖励。
- [ ] 临时 Store 错误不能被当成“不是首次”。
- [ ] Friend Link Saga 保存奖励资格步骤，崩溃后可以继续。

建议状态：

```text
RELATION_ACTIVE
-> FIRST_REWARD_CHECKED
-> REWARD_MAILS_CREATED
-> COMPLETED
```

### Task 4：创建双方奖励邮件

- [ ] 被邀请人首次奖励资格成功后创建两个稳定事件。
- [ ] 两个事件附件均为：
  - 10 金币；
  - 4 个葡萄种子。
- [ ] MailSvr 按 source event ID 去重。
- [ ] 第一封创建成功、第二封失败时，Saga 重试只补第二封。
- [ ] MailSvr 不可用时好友关系仍保持 ACTIVE。
- [ ] Saga 最终继续投递，不能回滚已经建立的好友关系。
- [ ] 非首次好友不调用奖励邮件创建。

建议测试：

```go

func TestNonFirstFriendDoesNotRewardEitherPlayer(t *testing.T)
func TestConcurrentFirstFriendClaimsRewardOnce(t *testing.T)

```

## 10. 停止条件

- 链接引入第二套好友关系写路径；
- GET 请求直接建立好友；
- 客户端能够伪造“首次好友”；
- 使用好友列表数量的非原子查询决定奖励；
- FriendSvr Store 错误被当成“不是首次”；
- 重试可能重复创建奖励邮件；
- Base URL 写死在业务代码；
- 本地链接实现依赖尚不存在的公网域名。
